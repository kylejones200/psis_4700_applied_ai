Let's begin with a shift in perspective. Up to now, most of what we've covered has focused on analyzing data—predicting outcomes, classifying inputs, extracting meaning. Generative AI does something different: it creates. Instead of taking existing data and producing a label or prediction, it produces entirely new content: images, text, audio. That feels powerful, and it is, but it also introduces a new category of risk. Because when a system creates something new, it can create something misleading, harmful, or incorrect just as easily as something useful. So this week has two themes that must stay connected: creation and responsibility. You will learn how these systems generate images, but just as importantly, you will learn how to control them, evaluate them, and deploy them safely. Generative capability without control is not useful in the real world.

Let's start with the landscape. Generative models exist across multiple domains: text generation with systems like GPT, image generation with systems like DALL·E or Stable Diffusion, audio generation with voice and music models, and increasingly multimodal systems that combine these capabilities. The important idea is not the modality—it is the structure. All of these systems learn patterns from data and use those patterns to generate new outputs. They do not copy directly; they generate based on learned distributions. That is what allows them to produce novel content, but it is also what makes evaluation more complex. Because there is no single "correct" output, there are many possible outputs, and you must decide which ones are acceptable.

Let's focus on the dominant approach for image generation: diffusion models. The idea is surprisingly simple. You start with noise—pure randomness—then you gradually remove that noise step by step. At each step, the model predicts what the image should look like with slightly less noise. Over many steps, structure emerges: shapes appear, details refine, and eventually you get a coherent image. This process is computationally intensive, but it produces high-quality results. The key insight is this: the model does not generate the image all at once; it builds it iteratively. That gives you control, because you can guide the process at each step. Before diffusion models, two other approaches dominated: variational autoencoders and generative adversarial networks. VAEs learn a compressed representation of data—a latent space—and you can sample from that space to generate new outputs. GANs use two networks: one generates images, the other evaluates them. They compete, and over time the generator improves. Both approaches were powerful, but they had limitations. GANs were difficult to train, and VAEs often produced blurrier images. Diffusion models addressed many of these issues, though understanding these earlier methods helps you see how the field evolved.

Now we move to how you control these systems. Prompting is central. In image generation, the prompt describes what you want—the subject, the style, the lighting, the composition. The more precise you are, the better the result. But there is another tool: negative prompts. You specify what you do not want, and this helps steer the model away from common failure modes. Then there is the concept of seeds. A seed controls randomness; if you use the same seed, you can reproduce the same image. This is important for iteration because it allows you to refine results systematically. Prompting gives you high-level control, while conditioning gives you fine-grained control. Tools like ControlNet allow you to guide the model using additional inputs—edge maps, depth maps, pose information. This lets you constrain the structure of the image; you are no longer relying only on text but guiding the generation process more directly. There is also the concept of guidance scale, which controls how strongly the model follows the prompt. Higher values enforce adherence; lower values allow more creativity. So you balance precision and variation.

Now we return to responsibility. Generative systems can produce harmful content, so safety filters are required. NSFW filters block inappropriate outputs, watermarking identifies generated content, and usage policies define what is allowed. These controls operate before and after generation—they filter prompts, they filter outputs, and they enforce boundaries. Because once the system is deployed, users will test those boundaries. Generative AI raises legal questions: where does the training data come from, and who owns the output? These questions are still evolving. Training data may include copyrighted material, outputs may resemble existing works, so you must understand the legal context and design systems that respect it. This is not only a technical issue; it is a business and legal one.

Evaluating generated images is not straightforward. You consider aesthetics—does it look good? You consider relevance—does it match the prompt? You consider diversity—can the system produce varied outputs? And you rely on human review, because automated metrics cannot capture all nuances. This makes evaluation subjective, but structured criteria help and provide consistency. Just like with chat systems, generative models must be tested: you probe for unsafe outputs, try adversarial prompts, log failures, and update policies. This process improves safety over time because it reveals how the system behaves under pressure. Image generation is computationally expensive, so cost and latency matter. You batch requests when possible, you cache results, and you choose model sizes based on need. These decisions affect scalability, because a system that works for one user may not work for thousands. The quality of outputs depends on the quality of training data. Diversity matters: if the dataset lacks variation, the model produces limited outputs. Deduplication prevents memorization, and bias awareness ensures outputs are balanced. This is where fairness begins—in the data.

Prompting can be standardized. Templates allow reuse: you define a structure, then you parameterize it. This creates consistency and allows teams to share patterns. Prompt libraries emerge from this; they capture what works and evolve over time. Generative systems increasingly combine modalities—text and image, audio and text—and this introduces alignment challenges. Outputs must be consistent across modalities; if text describes one thing and the image shows another, the system fails. So alignment becomes critical. Guardrails operate before and after generation: you filter prompts, filter outputs, and use classifiers to detect unsafe content. This layered approach reduces risk because no single control is sufficient. Generated content must be identifiable: watermarks mark outputs, provenance tracks origin, and this prevents deception. Users should know when content is generated; transparency builds trust. There are multiple providers, each with different capabilities, costs, and constraints, so choosing a platform is a design decision—not only technical, but operational. The lab brings this together: you build a text-to-image system, add filters, manage prompts, and evaluate outputs. This is where theory becomes practice.

Now step back. Where could generated images mislead users? In news, in medical imaging, in legal evidence—these are high-risk domains, and they require stronger controls. Negative prompts refine outputs by excluding unwanted elements, which improves control and reduces iteration. Seeds allow reproducibility and support experimentation and scientific rigor. Style transfer separates content from style: you preserve structure and change appearance, which enables creative applications. Inpainting edits regions, outpainting extends images, and both support iterative workflows and controlled editing. Classifiers detect harmful content before and after generation and enforce boundaries. Shared prompts improve consistency, and versioning tracks changes, which supports team collaboration. Consent matters, licenses must be respected, and opt-out mechanisms support fairness. Outputs must represent diversity and avoid stereotypes—this is both ethical and practical. Detection verifies provenance and helps identify manipulation. Generating multiple outputs provides choice; users select the best, and this improves quality. Final steps refine outputs: upscaling, color correction, artifact removal. These polish the result. Usage limits must be managed, and backoff and retry logic ensure stability. The reading list deepens understanding—diffusion models, safety frameworks—and these connect practice to theory. The assignment integrates everything: you build a system, document safety, and reflect on limitations. This is where capability meets responsibility.
