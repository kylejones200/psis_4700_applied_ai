Now that we understand how models learn, we can look at what they actually produce. At a high level, most applied AI systems do one thing: they predict. Sometimes they predict a number; sometimes they predict a category. But in both cases, they take what they have seen in the past and use it to estimate what will happen next. That leads to two fundamental types of problems: regression and classification. Regression deals with numbers; classification deals with categories. That distinction may sound simple, but it shapes everything about how a model behaves and how you interpret its output.

Take regression first. Imagine you want to predict the price of a house. You have features such as square footage, number of bedrooms, location, and age of the property. Each of these factors contributes to the final price. A regression model tries to learn the relationship between those inputs and the numeric outcome. In the simplest case, that relationship can be represented as a line. You fit a line through the data in a way that minimizes the difference between the predicted values and the actual values. That difference is the error. So the model learns a function that maps inputs to a number.

Now here is the important part. That line is not only a prediction tool; it is also a summary. It tells you how the system believes each feature influences the outcome. If the coefficient on square footage is positive, the model has learned that larger houses tend to cost more. If the coefficient on age is negative, it has learned that older houses tend to cost less. So regression gives you both prediction and interpretation. But that interpretation comes with a warning: the model captures correlation, not causation. If an important variable is missing, or if the data reflects hidden biases, the coefficients can mislead you. So you always have to interpret results in context.

Not all relationships are perfectly linear. Sometimes the data curves or changes in more complex ways. In those cases, a simple line may not be enough. You can extend the model, add features, or use more flexible approaches. But the core idea remains the same: you are mapping inputs to a number.

Now consider classification. Instead of predicting a number, you are assigning a category—spam or not spam, fraud or not fraud, approve or deny. At first glance this seems easier, but it introduces a different kind of complexity. Because categories are not always clean; there is often uncertainty. A classification model does not truly "know" that something is spam. It estimates the probability that it belongs to that class. So instead of a hard answer, the model produces a score between zero and one. That score reflects how confident the model is. Then you choose a threshold. If the score is above the threshold, you label it as positive; if it is below, you label it as negative. This is where decisions enter the system. The threshold is not purely technical; it reflects tradeoffs. If you set a low threshold, you catch more positive cases but you also increase false alarms. If you set a high threshold, you reduce false alarms but you miss more true cases. So classification is not only about prediction; it is about managing risk.

Consider fraud detection. If the model flags a transaction as fraudulent when it is not, you inconvenience a customer. If the model fails to flag a fraudulent transaction, you incur a financial loss. Those two errors are not equal. So you have to decide which one matters more. That decision determines how you set the threshold, and that in turn determines how the model behaves in practice. This is why probabilities matter more than labels. The label hides uncertainty; the probability exposes it. And good systems use that information to make better decisions.

Briefly consider some common model types. Linear and logistic regression are simple and interpretable; they work well when relationships are relatively straightforward. Decision trees take a different approach. They split the data into branches based on feature values. You can follow the path from root to leaf and see exactly how a decision is made. That makes them easy to explain, but they can also become unstable if they grow too complex. Random forests address that by combining many trees. Each tree sees a slightly different view of the data. When you aggregate their predictions, the result is more stable. This idea of combining models appears often; it reduces variance and improves performance.

Regardless of the model you choose, there is a common risk: overfitting. A model can become so focused on the training data that it captures noise instead of real patterns. When that happens, it performs well on known data but poorly on new data. The opposite problem also exists: underfitting. The model is too simple to capture the structure in the data; it misses important relationships. So the goal is not to build the most complex model. It is to build a model that generalizes—that means it performs well on data it has never seen before. This is why evaluation matters. You cannot judge a model based only on how it performs on the data it was trained on. You need to test it on new data. That gives you a realistic estimate of how it will behave in practice.

Regression and classification are not abstract concepts; they are the foundation of most applied AI systems. Any time you estimate a quantity, you are doing regression. Any time you assign a category, you are doing classification. And in both cases, the model is doing the same thing: it is taking patterns from the past and projecting them into the future. So the real question is not which algorithm you use. The real question is whether the prediction connects to a decision. Because that is where value is created. A prediction by itself does nothing; it becomes useful when it informs an action—approve a loan, flag a transaction, route a request, adjust a price. That connection from prediction to decision is what turns modeling into applied AI. And that is the lens you should keep as we move into evaluation next, because once you start making decisions, you need to know whether those decisions are any good.
