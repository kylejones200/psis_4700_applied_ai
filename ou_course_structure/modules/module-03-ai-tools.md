# Module 3: AI Tools and Models in Practice

## Module Overview

This module introduces AI tools as practical instruments rather than abstract technologies. Students learn how to compare options and select tools that fit real constraints. The focus stays on judgment, clarity, and justification rather than novelty.

## Module Learning Objectives

By the end of this module, students can:

1. Compare classical machine learning, large language models, and API based AI services.
2. Select appropriate AI tools for a given workplace use case.
3. Justify AI tool choices in plain language.

## Lesson 1: The Applied AI Tool Landscape

### Lesson Objective
This lesson supports the objective of comparing classical machine learning, large language models, and API based AI services.

### Lesson Overview
Most applied AI projects rely on a small set of tool categories. This lesson establishes a shared map of those categories and their typical roles.

### Core Content
Classical machine learning supports prediction and classification on structured data. These models offer control and stability. They require feature design and ongoing maintenance.

Large language models handle text and language driven tasks. They excel at summarization, extraction, and synthesis. They trade determinism for flexibility.

API based services abstract infrastructure and models behind managed endpoints. They reduce setup time and shift cost to usage. They limit customization.

Applied AI teams choose tools based on constraints rather than preference. The simplest viable option often wins.

### Worked Example
A forecasting task uses a classical model rather than an LLM. The data structure and error tolerance favor predictability.

### Check for Understanding
Students match tool categories to task descriptions and explain the fit.

## Lesson 2: Choosing Tools Under Constraints

### Lesson Objective
This lesson supports the objective of selecting appropriate AI tools for a given workplace use case.

### Lesson Overview
Tool choice reflects tradeoffs. This lesson teaches a constraint first approach to selection.

### Core Content
Cost shapes decisions. Usage based pricing affects scale. Latency affects user experience. Integration affects adoption.

Data access narrows options. Some tools require data movement. Others run in place.

Risk tolerance matters. Regulated environments favor transparency. Experimental teams accept uncertainty.

Good selection documents why alternatives fail. This protects teams later.

### Worked Example
A document workflow uses a managed embedding service due to security and integration needs. Custom training adds no value.

### Check for Understanding
Students select a tool for a scenario and justify the choice based on constraints.

### Required Material
Lesson reading provided in the LMS.

### Optional Enrichment
Decision matrices and examples provided in the course repository.

## Lesson 3: Explaining AI Choices to Stakeholders

### Lesson Objective
This lesson supports the objective of justifying AI tool choices in plain language.

### Lesson Overview
Applied AI succeeds when others understand it. This lesson focuses on communication rather than technical detail.

### Core Content
Stakeholders care about outcomes, risk, and cost. Technical depth matters less than clarity.

Effective explanations state the problem, the approach, and the reason for selection. They acknowledge limits.

Avoid jargon. Use comparisons. Explain what happens when the system fails.

Clear communication builds trust and support.

### Worked Example
A team explains why a rules based filter precedes an AI model. The explanation highlights cost control and reliability.

### Check for Understanding
Students rewrite a technical description for a non technical audience.

### Required Material
Lesson reading provided in the LMS.

### Optional Enrichment
Communication templates provided in the course repository.

## Module 3 Assignment: Tool Selection Brief

### Assignment Overview
Students select and justify AI tools for a proposed applied AI use case. The assignment emphasizes reasoning and clarity.

### Assignment Instructions
Students submit a brief. The brief describes the use case, selected tools, rejected alternatives, and the rationale for each decision. The language targets a non technical stakeholder.

### Assessment Criteria
- Tool selection aligns with stated constraints.
- Rejected alternatives are justified.
- The explanation uses clear and direct language.
- Risks and limits are acknowledged.

### Alignment
This assignment assesses Module 3 objectives two and three and Course Learning Outcomes two and four.
